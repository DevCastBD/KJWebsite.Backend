## 1. Where we are

Four services behind a YARP gateway, runnable with `dotnet run` (Auth and CTA need a local PostgreSQL 17; Content is in memory):

| Service | Port | State |
|---|---|---|
| ApiGateway | 7000 | Routes hard-coded in `Program.cs`; `/health`; no CORS, auth or rate limiting |
| ContentService | 7001 | Projects + news read/admin; **in-memory**; admin auth is the literal `dev-admin-token` |
| CtaSubmissionService | 7002 | `POST /api/v1/cta/submissions`; PostgreSQL (Npgsql, own schema); allow-list validation, 32 KB cap |
| AuthIdentityService | 7003 | Register/login/refresh/logout/me; **plain-text passwords**, GUID tokens in a process dictionary |

Done in P0: README with security notice, PROJECT_CONTEXT, central build config, BuildingBlocks (Problem Details, `Result`, paging, language), test projects, legacy snapshots moved to `legacy/`, legacy email template, ADR-001.

**Gaps that block a public deployment** (all still present): G1 plain-text passwords · G2 opaque tokens in memory · G3 `dev-admin-token` · G4 content not persisted · G5 no CORS · G6 no rate limiting · G7 no production database · G25 content response shape ≠ what the frontend expects, and no `/content/bootstrap`. Plus: no email delivery (G11), no outbox (G28), CTA submissions write-only (G15), no backups (G29).

> **Do not deploy the current `develop` publicly.** G1–G3 make it trivially compromisable.

## 2. Ground rules

1. **The frontend never waits for us.** It ships statically and switches features on at runtime when our endpoints exist. Unblock it first: CORS → `/content/bootstrap` → persistence.
2. **No CI/CD, Docker or automation at this stage.** No GitHub Actions, Dependabot, Dockerfiles or Compose. Run services with `dotnet run`; run checks locally before each PR: `dotnet build`, `dotnet format --verify-no-changes`, `dotnet test`, `dotnet run --project tools/OpenApiExporter -- --verify`. Deploy by hand. Automation is reconsidered once the API is deployed.
3. **Tests need no Docker.** SQLite by default; a local PostgreSQL is opt-in via environment variable (BE-001).
4. **Additive contract changes only.** Keep `openapi.v1.yaml` current; breaking changes wait for `v2`.
5. **ADR-001 with deferred extras.** Keep independently deployable services, but co-host them behind the gateway. Service-to-service auth, a service registry and distributed tracing are deferred until a service runs on a separate host (BE-093).

## 3. Architecture (short)

```
Browser (static SPA, works without us)
   │
   ▼
ApiGateway (YARP) ── CORS, rate limits, routing from config, /health
   ├── Identity ─────┐
   ├── Content ──────┤── PostgreSQL (schema per service)
   ├── Engagement ───┤
   └── later: Membership, Finance, Events, Communications, Reporting
```

Each service owns its folder, `DbContext`, migrations and schema; no service writes another's tables. Shared code lives in BuildingBlocks. Workers, Redis and object storage are added only when a feature needs them.

| ADR | Decision |
|---|---|
| 001 | Independently deployable microservices behind YARP (accepted); cross-service extras deferred (BE-093) |
| 002 / 003 | ASP.NET Core Identity; asymmetric JWT (15-min access) + rotating refresh tokens stored hashed |
| 004 | PostgreSQL 17, service-owned databases and schemas (Npgsql); accepted, see [ADR-004](adr/0004-postgresql-per-service.md); tests use SQLite |
| 005 | Hangfire or Quartz + transactional outbox for side effects |
| 006 / 007 | S3-compatible object storage (R2/S3); transactional email provider with DKIM/SPF |
| 008 | bKash + Nagad + SSLCommerz; Stripe/PayPal for diaspora donors |
| 009 – 011 | FluentValidation; explicit/Mapperly mapping; Serilog (OpenTelemetry tracing with BE-093) |
| 012 | xUnit + FluentAssertions + WebApplicationFactory on SQLite; optional local PostgreSQL (no Testcontainers) |
| 013 | Hosting chosen on cost (decision BE-027); manual `dotnet publish` deploys, no containers for now |
| 014 | Data residency and retention (decisions BE-051) |

**API conventions.** `/api/v1/{module}/…` public, `/api/v1/admin/{module}/…` authenticated · RFC 9457 Problem Details · paging envelope `{ items, total?, nextCursor?, limit, offset? }` (max 100) · `?lang=bn|en` with the resolved language in the response; admin endpoints return all translations · `Idempotency-Key` on public POSTs · `ETag`/`If-Match` on admin updates · ISO-8601 UTC dates, no localised numerals · slugs as public identifiers · `/health` per service and at the gateway.

## 4. Security baseline (before any public deployment)

Hashed passwords (Identity) · JWT + hashed rotating refresh · permission-based authorisation, deny by default · CORS allow-list from config · rate limits on login/register/CTA · validation on every input · secrets only in environment variables · TLS + HSTS · PII never logged · backups with a tested restore. Later phases add: audit log (P2), PII encryption + retention (P3), financial controls + webhook signatures (P4).

## 6. Frontend alignment

| Backend delivers | Frontend turns on | Until then the frontend… |
|---|---|---|
| BE-004 CORS + `/health` | Backend probe reports `up` | runs fully static |
| BE-006 `/content/bootstrap` (+ BE-009 persistence) | `apiContent` | renders committed snapshots |
| CTA endpoint + CORS (+ BE-030 idempotency) | `apiCta` | delivers forms by `mailto`/Formspree |
| BE-014 – BE-018 auth | `auth`, later `admin` | hides login and admin |
| P2+ modules | the matching flags | builds against MSW; entry points hidden |

Rules: agree the OpenAPI change first; deploy the endpoint before the frontend enables its flag in production; never require a frontend change to keep a published page rendering.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Current auth deployed publicly before BE-019 | Do-not-deploy notice; G1–G3 tracked and verified in order |
| Microservice overhead slows a volunteer team | Co-host everything, defer s2s/registry/tracing (BE-093), track hosting cost |
| No CI means broken builds or contract drift slip in | Local checks in every PR; OpenAPI `--verify` before merge; reconsider CI after first deployment |
| Payment merchant approval takes months | Raise BE-053 at the start of P2; build on sandboxes; offline donations first |
| Financial correctness bugs | Double-entry ledger, append-only records, ≥ 90 % tests on finance, external review |
| Personal data mishandled | Minimal collection, retention policy (BE-051/052), PII never logged |
